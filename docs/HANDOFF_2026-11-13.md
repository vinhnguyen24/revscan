## 1. Đã làm trong phiên này

### 1.1 Chốt định vị (quan trọng nhất)

Ba lần bị chỉnh hướng, và lần cuối là đúng:

1. Ban đầu định bán **license server + anti-REA SDK** → user chỉ ra: key verify là
   commodity, không ai trả tiền.
2. Chuyển sang **protect (chèn trap)** → user chỉ ra: mua 1 lần rồi copy được.
3. Cuối cùng: **scan là sản phẩm**, vì dev cần biết "app mình bị bẻ trong bao lâu".
   Protect/monitor là bước sau. License server chỉ còn là add-on, không lên trang chủ.

Ghi lại để phiên sau không quay lại phương án 1/2.

### 1.2 Engine scan (`scanner/`, `scan.py`)

- Đọc PE thật: section + entropy, imports, exports, `.pdata` (đếm hàm native **chính xác**).
- Đọc .NET metadata thật: `MethodDef`/`TypeDef`, tên method, IL bytes (có bound).
- `ident.py`: tách camelCase + underscore rồi match cả từ, để không khớp
  `m_userSerializationData` / `VerificationContext`.
- Cost model minh bạch: `tool + read_budget/prefill + rounds*1200/decode`.
- `risk = p_success * ease(seconds)`, in cả p_success và độ không chắc chắn.
- `--json`, `--min-seconds` (CI gate), `--ai` (đo thật).

Số đã đo trên binary thật:

| File | model | p | ghi chú |
|---|---|---|---|
| notepad.exe | 72s | 0.35 | không có license logic → "unlikely" |
| notepad + string license | 61s | 0.85 | string giúp agent tìm nhanh |
| cùng file + protect L2 | 71s | 0.55 | trap làm chậm + giảm p |
| mscorlib.dll (27.492 methods) | 48s | 0.90 | .NET lộ tên hàm |
| WindowsCodecsRaw.dll (32MB) | 1.8 phút | 0.70 | tool time scale |
| amd_comgr_2.dll (110MB) | 2.5 phút | 0.70 | 110MB scan trong 1.0s |

### 1.3 Calibrate (`calibrate.py`)

- `calibrate.py`: batch scan thư mục, fit **một** multiplier `k` trên phần biến thiên
  (tool time không scale), **theo đúng band model đã đo** (`--ai` với Ollama → `local-20b`).
- Geometric mean, loại mẫu model không tìm ra check.
- Cảnh báo khi `spread > 3x` (thiếu tín hiệu).
- `TRAPKEY_CALIBRATION_K` (+ `TRAPKEY_CALIBRATION_MODEL`) được `estimate.py` đọc → áp ngay vào scan.

### 1.4 Web SaaS (`web/`)

Zero npm dependency, zero build step:

- `/`, `/scan`, `/pricing`, `/login`, `/legal/privacy`, `/docs/calibration`
- `/r/:publicId` (share được, người lạ chỉ thấy tóm tắt)
- `/app`, `/app/scan/:id` (owner), `/app/settings` (CI token, xoá account)
- `/app/admin` (key qua POST form → cookie HttpOnly; đổi gói ghi `events`)
- Magic link auth (hash trong DB, dùng 1 lần, 15'), session cookie httpOnly
- Credit 2 bucket + ledger + reset 30 ngày + quota anonymous 1/ngày/IP
- Cache theo `sha256` 24h → không trừ credit
- Invoice mode khi chưa có Stripe (không link chết)
- Upload stream 150MB, xoá file ngay, sweep file cũ lúc boot

### 1.5 Protect (phần đã có, không phải trọng tâm)

- `cli/trapkey.py protect` chèn payload vào PE: slack → new section → overlay.
- Đã chứng minh file vẫn chạy: `hostname.exe` trước/sau protect in cùng hostname.

### 1.6 Review + hardening (cùng ngày, sau khi chạy lại toàn bộ)

Các lỗi tìm thấy khi review phần trên, đã sửa + có test hồi quy:

- `--ai --json` crash `KeyError('measured')` (web AI mode chết khi có model) → `measured`
  tách khỏi `est.seconds`; headline không còn `~0s`.
- Fit `k` sai đại lượng (trừ tool time khỏi số đo không chứa tool time) → `k = measured /
  (model - tool)`, fit theo band thật (`TRAPKEY_CALIBRATION_MODEL`).
- Cache web thiếu `mode` → scan AI trả lại report static.
- UTF-16 strings bị ASCII 60k "bỏ đói"; `packed` so sai hoa/thường; Electron xoá hình
  phạt protection; budget nhánh "không tín hiệu" không cap; `k` âm/NaN.
- Magic link: `UPDATE ... WHERE used=0` trong transaction (hết race dùng lại link).
- Anonymous chỉ nhận summary (top 3 leak, không `fix`) thay vì full report JSON.
- Engine stderr chỉ vào log server; admin key qua POST + cookie HttpOnly (không query).
- Test path không còn hardcode `/mnt/c`; CI Ubuntu + Windows (`.github/workflows/ci.yml`).

### 1.7 Protect v2 (cùng ngày)

- `cli/pe.py:strip_debug()`: zero data-directory entry #6 + CodeView (RSDS/NB10/`.pdb`)
  → mất đường dẫn build, mất finding `pdb-path`.
- Payload v2 (`--level 2/3`): chunk theo `id`, mã hoá bằng seed dẫn xuất từ chính build
  (`build_seed = sha256(build + payload)`), seed lưu obfuscated trong blob nên agent vẫn
  decode được; level 3 thêm 2 decoy chunk (`0xFFFE/0xFFFF`).
- `trapkey info` đọc payload v2 (chunk/decoy/seed prefix).
- `--sig/--pubkey`: từ chối payload bundle không do vendor ký (RSA PKCS#1 SHA-256).
- Đo trên notepad: 72s → 83s, p 0.35 → 0.05; notepad + licence strings: 61s → 71s,
  p 0.85 → 0.55. File vẫn là PE32+ hợp lệ, chưa test chạy trên Windows thật.

### 1.8 Calibrate lần đầu (cùng ngày)

- Gateway nội bộ OpenAI-compatible (`aiproviders.s3corp.com.vn/v1`), model
  `ollama/gpt-oss:120b`; key để trong `.env` (gitignored), không commit.
- Run 1: `k=0.1413`, `n=4`, spread 2.2x (1 call/file; call đầu batch bị cold-start).
- Run 2: `k=0.0808`, `n=9`, spread 2.77x, `--repeat 3`; so 1 call với workload giả định
  1200 output tokens nhưng model chỉ sinh ~250 → k thấp giả tạo. Bỏ.
- Run 3 (chốt): `k=0.2758`, `n=10`, spread 1.87x, `--repeat 5`, chuẩn hoá theo token
  thật (`prompt_tokens/prefill + completion_tokens/decode`) → k là **speed factor**.
  8 thư viện .NET licensing (NuGet) + `WinRAR.exe` + Sublime Text portable;
  `WinRAR.exe` 70s → 39s, `sublime_text.exe` 84s → 50s.
- Sửa kèm theo: `--ai` đổi prompt sang "audit, locate" (prompt cũ xin keygen bị model
  từ chối), `max_tokens` 400 → 1200 (reasoning model ăn hết budget), success chỉ tính
  khi `FUNCTION:` là tên/địa chỉ thật (`none`/`unknown`/`unresolved` = fail), pack gửi
  kèm `license_named_functions` + `license_strings` (đúng thứ agent grep được),
  `--repeat` lấy median qua N lần.
- Fit theo **workload token thật** của call (`prompt_tokens/prefill +
  completion_tokens/decode`), không phải một-round/all-round giả định → k là speed factor.
- So sánh model: `nemotron-3-ultra` `k=1.8928` (n=9, spread 3.27) — chậm hơn ~6.9x;
  GPT-5.6/Kimi/GLM trả "unknown/insufficient evidence" trên native vì pack không có
  disassembly. Giữ `gpt-oss:120b` (`k=0.2758`) làm worst-case (thời gian ngắn nhất).
- Chi tiết + bảng đo: `docs/CALIBRATION.md` §8.

## 4. Việc tiếp theo, theo thứ tự

### Bước 1 — Calibrate (làm trước tiên, rẻ, giá trị cao)

```bash
# miễn phí trước, để chắc pipeline chạy
TRAPKEY_AI_PROVIDER=ollama TRAPKEY_AI_MODEL=qwen2.5-coder:7b \
  python3 calibrate.py ~/binaries --ai --limit 10 --out calib.json

# hoặc provider mạnh (mối đe dọa thật)
OPENAI_BASE_URL=https://api.deepseek.com/v1 OPENAI_API_KEY=sk-... \
  TRAPKEY_AI_MODEL=deepseek-chat \
  python3 calibrate.py ~/binaries --ai --limit 10
```

Ghi vào `docs/CALIBRATION.md`: `k`, model, ngày, `n`, `spread`.
Nếu `spread > 3x` → đừng ghi `k`, đi sửa tín hiệu trước.

### Bước 2 — Đưa `k` vào web (✅ đã làm 2026-11-13)

- `web/scanjob.js`: env được kế thừa; đặt `TRAPKEY_CALIBRATION_K` +
  `TRAPKEY_CALIBRATION_MODEL` trong env của service.
- `views.reportView`: đã hiện dòng `calibrated` (k + band), `nguồn số`
  (`model` / `model+measured`) và `đo thật (1 round)` khi có.
- Cache theo `sha256` đã tính cả `mode` (trước đó scan AI trả lại report static).

### Bước 3 — Protect v2 (✅ phần lớn đã làm)

Đã có: strip debug/PDB (`cli/pe.py:strip_debug`), payload v2 mã hoá theo build + chunk +
decoy, `--sig/--pubkey` để từ chối payload feed không ký, `trapkey info` đọc payload.
Còn lại: stub runtime giải mã (reference từ code) và server payload feed
(endpoint + rotate + revoke). Đừng làm VM/CFL tự viết.
